# term4u 代码库调整设计文档

本目录是 **term4u** 项目的代码库调整设计文档集。term4u 是 Warp 开源客户端
（`warpdotdev/warp`，基线提交 `066ec71b736fc3755e29f58f733deadbdac3d1af`）的
本地化 / 离线化衍生版本。

**本文档只描述"要做什么、为什么、怎么验收"，不包含任何已执行的代码改造。**
截至本文档提交时，仓库仍是上游快照的原样，未做任何功能性修改。

| D7 | **交付节奏** | **V0** = 调研第 1–5 步（主体是删除），产出可日常使用的本地构建；**V1** = 第 6–8 步；**V2** = 品牌与对外发布。 | [01 §6](01-背景与目标.md#s6) |

## 三、术语表

| 术语 | 含义 |
|---|---|
| **上游 / upstream** | `warpdotdev/warp`，默认分支 `master`，基线 HEAD `066ec71b736fc3755e29f58f733deadbdac3d1af`。 |
| **快照** | 本地工作目录中未提交的 29 个未跟踪条目，即上游 `066ec71` 剥离 dotfiles 后的整份内容。 |
| **MIT 岛** | `crates/warpui` + `crates/warpui_core` 两个 crate。全仓库仅此二者 `license = "MIT"`，其余（含 `warpui_extras`）都是 AGPL。 |
| **AGPL 闭包** | MIT 岛通过 path 依赖可达的 AGPL workspace crate 集合。阶段 2 抽取 MIT 岛必须先解开这个闭包。 |
| **端点单点** | `crates/warp_core/src/channel/config.rs` —— 全部生产 URL 与 Firebase key 的唯一硬编码位置。 |
| **Channel** | Warp 的构建通道概念（`Oss` / `Local` / `Dev` / `Preview` / `Stable` / `Integration`）。每个 channel 对应一个 bin 与一份 `ChannelConfig`。 |
| **`offline_hard`** | 拟新增的**跨 crate** feature：编译期切断云代码 + 运行期在 socket 对端地址层硬拒绝非 loopback 出站。 |
| **`local_only`** | 拟新增的**加法定义**顶层 feature：`offline_hard` + 本地能力集。构建用 `--no-default-features --features local_only`，**不从现有 `default` 做减法**。 |
| **choke point** | 少数几个"改一处、连带修好一大片测试"的文件。见 [07 §4](07-测试与验证策略.md#s7-4)。 |
| **类 A / 类 B / 类 C** | 删除对测试的三种破坏形态：随模块消亡 / 编译期断裂 / 行为漂移。见 [07 §3](07-测试与验证策略.md#s7-3)。 |
| **presubmit** | `script/presubmit`。本仓库**没有 `.github/`**，因此它是"绿色基线"的唯一定义。 |
| **null object** | 空实现对象模式。此处特指保留 `ServerApi` 类型签名、所有方法返回"离线"错误或空值，从而让调用方与测试同时存活。 |
| **V0 / V1 / V2** | 交付阶段，见 D7。 |
| **阶段 1 / 阶段 2** | 许可证形态阶段：阶段 1 = AGPL+MIT 双许可 fork；阶段 2 = 完整 MIT 重实现。 |

## 四、本文档集的事实纪律

1. **每个数字都可复现。** 文档中的文件数、行数、命中数都附带产生它的命令；
   读者可以自己跑一遍。数字随代码变化，命令不会。
2. **区分"实测"与"待核验"。** 凡是本轮未在本机验证的（例如上游 GitHub 仓库
   的当前许可证状态），一律显式标注 `【待核验】` 并给出核验方法与时机。
3. **修正优先于沿用。** 调研原文与本审计冲突时，以审计为准，并在
   [附录A](附录A-上游调研原文.md) 的修正对照表中逐条登记，不静默覆盖。
4. **验收标准必须可执行。** 07 / 08 两章的每一条验收都是一条可运行命令或一个
   可观察产物，不出现"确认无误""检查一下"这类不可执行表述。
