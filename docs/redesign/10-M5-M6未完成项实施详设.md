## 一、目标与完成定义

### 1.1 M5 完成定义

M5 完成时，产品代码中不再存在可触达的 Warp 云认证、Drive/cloud object 同步、Warp Agent
云运行链、TUI 云会话、LSP 自动下载及 Warp 云站点入口；只保留本地终端、编辑器、文件树、
本地 workflow、离线可用的 notebook 数据和 PATH 中已有的 LSP。

M5 **不是**以“`offline_hard` 能拦住请求”为完成标准。守卫只作为兜底；M5 的目标是让云功能
入口、初始化、重试任务和业务实现本身消失。

### 1.2 M6 / V1 完成定义

M6 完成时：

1. 八个云 crate 从 workspace、manifest、正常依赖树和 `Cargo.lock` 中消失；
2. `session-sharing-protocol` 和 `warp_multi_agent_api` 不再出现在 `local_only` 正常依赖树；
3. `app/src/server/graphql/`、云 `ServerApi` 和过渡期 `OfflineApi` 被删除；
4. `deny.toml` 不再按组织放行 git 依赖，所有保留 git 来源显式列举；
5. `email_address` 使用精确 `rev`，不再跟随 `branch = "main"`；
6. GUI/TUI、测试和发布构建均通过，V1 依赖树及最终二进制黑名单为空。

## 二、不可破坏的本地能力

每批删除前先识别保留面；编译通过不代表行为仍在。

| 必须保留 | 验证方式 |
|---|---|
| 本地 PTY、shell 启动、命令执行和 Ctrl-C | GUI integration 的本地 shell 场景 + TUI 真实终端冒烟 |
| 标签页、分栏、窗口恢复 | 现有 pane/workspace 单测 + GUI 手工场景 |
| 编辑器、文件树、本地文件搜索、code review | 相关 crate/app 测试；至少打开、编辑、保存一个本地文件 |
| 本地和项目 workflow | `LocalWorkflows` 单测；从本地配置加载并执行一个 workflow |
| 旧数据库可加载 | 改造前 SQLite fixture + 一份 detached 基线生成的真实数据目录 |
| notebook 的本地读取、编辑与恢复 | legacy notebook fixture 打开、修改、退出、重启后内容不丢 |
| PATH 中已安装的 LSP | 用假的 PATH server 验证检测与启动；不得发生版本查询或下载 |
| 本地日志、panic 日志和日志打包 | [09 §11](09-第一次实施详设-V0.md#s11) 的 L1–L3 |
| 本地 skills 资源 | bundle resources 扫描；运行和 bootstrap 不下载或更新 skills |
| macOS 与 Linux | 本地便宜门禁通过后，按 §10 选择最小远端矩阵 |

以下能力明确删除，不需要保留兼容 UI：Warp 登录/账号、Warp Drive、团队/计费/推荐、Warp
云 Agent、云 runner、handoff、API key 管理、云同步、共享会话和自动下载。

**外部 CLI agent 的边界**：仍可作为用户在 PTY 中启动的普通子进程运行；删除 Warp 专有的
Agent SDK、rich-input、云编排和凭据注入，不替用户限制普通 shell 子进程的网络。

## 三、实施前必须冻结的决策

### 3.1 blocklist 路线

本文主路径采用 [03 §12](03-阶段1-云模块删除与离线化.md#s12) 的 **路线 A：删除 Warp Agent
UI 与执行层**。理由：

- M5.3 已要求删除 `agent/`、`agent_sdk/`、`agent_management/` 和 `ai_assistant/`；
- 当前 blocklist 仍直接调用 `ServerApiProvider` 和 `warp_multi_agent_api`，保留它会阻止 M6
  的两个核心黑名单归零；
- 阶段 2 的本地 agent 协议尚未冻结，不能以“以后也许复用”为理由永久保留 12 万行云 UI。

开工前创建 `docs/redesign/baseline/blocklist-decision.md`，至少记录：

```text
DECISION: route-a
BASE_HEAD: <sha>
OFFLINE_API_CALL_SITES: <rg 实测>
BLOCKLIST_TEST_FILES: <find 实测>
PHASE2_REUSE_DECISION: 不直接复用；未来按 agent_protocol 重新设计适配层
APPROVED_BY: <负责人>
DATE_UTC: <时间>
```

执行命令：

```bash
rg -n 'ServerApiProvider|get_ai_client|get_factory_client' app/src/ai/blocklist \
  | tee /tmp/m5-blocklist-server-api.txt
find app/src/ai/blocklist -type f -name '*tests.rs' | sort \
  | tee /tmp/m5-blocklist-test-files.txt
wc -l /tmp/m5-blocklist-server-api.txt /tmp/m5-blocklist-test-files.txt
```

如果负责人决定路线 B，**停止执行本文 M5.3/M6.2 主路径**，另写增量设计，明确本地 agent
runtime、协议类型归属及 `ServerApi` 替代方案；不得在删除过程中临时改路线。

### 3.2 本地数据模型策略

`app/src/cloud_object` 当前同时承担“云同步”和“本地对象容器”职责。不能直接整目录删除，
否则 notebook、workflow 和部分 env-var 类型会一起消失。

本次固定采用：**先提取本地数据模型，再删除云同步模型**。

- Warp 衍生的数据模型仍为 AGPL，不得复制到声明为 MIT 的 `crates-local/` crate。
- `Workflow`、`Argument`、`ArgumentType` 移入 `app/src/workflows/model.rs`。
- notebook 可持久化数据移入 `app/src/notebooks/model.rs`，继续读取已有 SQLite/JSON。
- 仍被本地 workflow 或 shell 初始化使用的 `EnvVar`/`EnvVarValue` 移入
  `app/src/env_vars/model.rs`；只服务 Drive 的 collection/权限/分享类型删除。
- 新建 `app/src/local_objects/`，只保留本地读取、写入、恢复所需的 store 和 ID 适配；不得
  出现 HTTP client、ServerApi、revision upload、permission、team、share 或 sync queue。
- 保留历史 migrations 和现有表；删除运行时代码不等于删除旧 DB 结构。

### 3.3 历史数据策略

- 不删除 `crates/persistence/migrations/` 中任何既有 migration。
- 不新增“清空 Drive/Agent 数据”的 migration。
- 已移除功能的数据按原始 JSON/列保留但不加载到 UI。
- 无法解析的旧云对象不能阻止应用启动；记录 warning 后跳过，日志不得包含对象正文或密钥。

### 3.4 Windows 边界

删除 W6–W9 的平台专属实现、module 挂载和 target dependencies，但继续遵守 D11：

- 不全仓清理散落的内联 `#[cfg(windows)]`；
- `crates/command/src/windows.rs` 与 `crates/warp_util/src/path/windows.rs` 保留到阶段 2；
- 名称中含 `windows` 的历史数据库 migration 不是平台代码，不删除；
- 混合平台 dependency block 必须拆分为 macOS/Linux/FreeBSD，不得误删这些平台所需依赖。


## 五、通用施工纪律

1. 每批先移除入口和调用方，再删实现，最后删 manifest/lockfile 依赖。
2. 每批一个可独立回滚的 commit；不得把 M5 全部压成一个无法定位回归的大提交。
3. 删除测试前先确认测试只覆盖被删能力；保留能力的测试必须迁移到本地实现，不能一起删除。
4. 禁止新增 `#[allow(dead_code)]`、新增 `#[ignore]`、注释测试或用 wildcard match 掩盖断裂。
5. Rust 测试放在独立 `*_tests.rs` 文件，并在源模块末尾通过 `#[path = "..."]` 引入。
6. 每批执行测试清单更新；`deleted-test-ids.txt` 必须保持“实际消失测试”的精确全集。
7. 不在删除过程中新增假服务器 URL、空 token、静默重试或 `todo!()` 作为过渡。
8. 不新增 `model.lock()`；修改终端路径时复用已有锁，避免重入死锁。
9. GUI/TUI 是两个前端：GUI 用 app/integration 验证，TUI 用 render-to-lines 和真实终端验证。
10. 任何源码变化都会使旧验证结果失效；最终验收必须重跑。

每批测试清单更新模板：

```bash
./script/test_inventory snapshot <batch>-after
comm -23 \
  docs/redesign/baseline/phase1-before.txt \
  docs/redesign/baseline/<batch>-after.txt \
  > /tmp/deleted-test-ids.next
comm -13 \
  docs/redesign/baseline/deleted-test-ids.txt \
  /tmp/deleted-test-ids.next \
  > /tmp/newly-deleted-test-ids.txt

# 人工逐条确认 /tmp/newly-deleted-test-ids.txt 都属于本批被删能力后：
cp /tmp/deleted-test-ids.next docs/redesign/baseline/deleted-test-ids.txt
./script/test_inventory
```

每批删除集保存在
`docs/redesign/phase1-acceptance/m5-m6/batches/<batch>-deletion-set.txt`；
`script/deletion_set.txt` 在施工期间指向当前批次的精确删除范围，不能继续保留上一轮
AWS/MCP 清单冒充当前范围。

### 10.4 跨平台顺序

1. 先在本机完成 focused tests、clippy、presubmit 和依赖负证明。
2. 确认待测 commit 已推到可访问远端；未经用户授权不得为跑云验证擅自 commit/push。
