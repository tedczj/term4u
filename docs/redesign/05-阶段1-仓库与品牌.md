## 一、git 拓扑重整（M0 第一步）

<a id="s1-1"></a>
### 1.1 起点（实测）

| 事实 | 值 |
|---|---|
| 本地目录 | `/Users/ted/workspace/term4u` |
| 当前分支 | `main`，**零提交**（`git log` → `fatal: your current branch 'main' does not have any commits yet`） |
| 工作区 | 29 个未跟踪条目（整份快照） |
| **`origin`** | **已经指向 `git@github.com:warpdotdev/warp.git`，且 SSH 可达** |
| 上游默认分支 | **`master`** |
| 上游 HEAD | `066ec71b736fc3755e29f58f733deadbdac3d1af` —— **与快照基线一致** |
| 目标远端 | `git@github.com:tedczj/term4u.git`，已创建、完全为空 |

> **这个起点比预想的好**：`origin` 已经配好且可达，所以不需要重新 clone。
> 整个重整就是 fetch + 改名 + 建分支。

<a id="s1-2"></a>
### 1.2 步骤

```bash
cd /Users/ted/workspace/term4u

# ── 1. 取回完整上游历史（注意分支名是 master 不是 main）────────────────────
git fetch origin master
git rev-parse origin/master        # 期望：066ec71b736fc3755e29f58f733deadbdac3d1af

# ── 2. 重命名远端：origin → upstream，新 origin 指向 term4u ─────────────────
git remote rename origin upstream
git remote add origin git@github.com:tedczj/term4u.git
git remote -v                      # upstream=warpdotdev/warp, origin=tedczj/term4u

# ── 3. 【验收点】先核验快照 == 上游，再动工作区 ──────────────────────────
#    ⚠️ 绝对不要用 `git reset --hard upstream/master`。
#    HEAD 未出生时索引为空，那 29 个快照条目全是 untracked，
#    而 `reset --hard` 会**静默覆盖** untracked 文件 —— 快照若与上游有任何
#    差异，证据会当场被销毁，随后的 `git status` 必然为空，验收变成空转。
#
#    用一次性索引做纯只读比对：
TMP=$(mktemp -u /tmp/m0idx.XXXX)
GIT_INDEX_FILE=$TMP git read-tree upstream/master
GIT_INDEX_FILE=$TMP git diff --name-status upstream/master -- . > /tmp/m0diff.txt
awk '{print $1}' /tmp/m0diff.txt | sort | uniq -c      # 期望：只有 D（缺失的 dotfile）
grep -vE $'\t\.' /tmp/m0diff.txt                       # 期望：空 —— 非 dotfile 零差异
rm -f $TMP

# ── 4. 以 upstream/master 为基建立 main（--mixed 不动工作区）───────────────
git symbolic-ref HEAD refs/heads/main    # HEAD 指向 main，纯 ref 操作
git reset --mixed upstream/master        # main := 上游；索引同步；工作区原封不动
git status --porcelain                   # 期望：仅 109 个 D + docs/ 等 ??
git checkout -- .                        # 把被剥离的 dotfiles 从索引写回工作区
git status --porcelain                   # 期望：只剩 ?? docs/

# ── 5. 首推 term4u ─────────────────────────────────────────────────────────
git push -u origin main
```

<a id="s1-3"></a>
### 1.3 第 3 步是快照真实性的验收点（已执行，通过）

**这一步同时验证两件事**：

1. **快照确实等于 `066ec71`** —— 如果 `git status` 非空，说明快照被改动过（或者
   剥离的不只是 dotfiles），必须先查清楚再继续。
2. **哪些 dotfiles 被剥离了** —— `.github/`、`.gitignore` 等如果 fetch 后出现，
   就直接可用，不必从零起草（见 [§2](#s2)）。

> **如果非 dotfile 差异非空**：先把 `/tmp/m0diff.txt` 存证，逐项判断是"快照工具的
> 正常差异"（换行符、文件权限）还是"实质改动"。在弄清之前**不要 commit**，
> 否则会把不明来源的改动混进第一个提交。

#### 实际执行结果（已完成）

```
差异条目总数: 109      按状态: 109 × D（present in upstream, missing locally）
非 dotfile 差异: 0     ← 快照与上游 066ec71 逐字节一致
反向多出的:      docs/（本文档集）+ todo.md
```

**结论：快照 ≡ `upstream/master` 剥离 109 个 dotfile 文件。** 两项都通过。
建立 `main` 后 `git status` 显示 **0 个 modified**，这是最硬的证据——
如果快照被改过，`--mixed` 之后必然出现 `M`。

<a id="s1-4"></a>
### 1.4 产出

| 产出 | 价值 |
|---|---|
| 完整上游历史 | 可以 `git log`、`git blame`、`git bisect` 到上游任何一个提交 |
| 独立远端 `origin` | term4u 的改动推到自己的仓库，不碰上游 |
| 长期 `git merge upstream/master` 能力 | 这是 [决策 N1](01-背景与目标.md#s5)（不改 crate 名与符号）存在的全部理由 |

<a id="s1-5"></a>
### 1.5 上游合并的长期节奏

| 项 | 建议 |
|---|---|
| 频率 | 每 1–2 个月一次，或上游发重要修复时 |
| 方式 | `git fetch upstream && git merge upstream/master`（**merge 不 rebase**——rebase 会重写 term4u 的历史，让下一次合并更难） |
| 冲突预期 | 主要集中在 `app/src/lib.rs`（三分改造）、`app/Cargo.toml`（feature 表）、`crates/warp_core/src/channel/*`（ConnectivityMode）。这三处是"改动集中"的代价，也是它的收益——冲突可预测 |
| 不合并的部分 | 上游对已删模块的改动会表现为"delete/modify 冲突"，一律选 delete |

> **⚠️ `.gitattributes` 的 LFS 规则是一个真实障碍**：
>
> ```
> *.pdb filter=lfs diff=lfs merge=lfs -text
> crates/input_classifier/models/** filter=lfs diff=lfs merge=lfs -text
> ```
>
> `crates/input_classifier/models/onnx/bert_tiny_v{1,2,3}.onnx` 在仓库里是
> **133 字节的 LFS 指针**，真实模型存在 warpdotdev 的 LFS 服务器上。
> fork 到 `tedczj/term4u` 只会带走指针，**带不走对象**。
>
> 三个选项：① 装 `git-lfs` 并在 warpdotdev 的 LFS 还可匿名访问时
> `git lfs fetch --all` 把对象拉下来、再推到自己的 LFS；② 判断
> `crates/input_classifier` 是否属于删除范围（它是本地输入分类器，**应保留**）；
> ③ 若模型拉不到，把这三个文件从 LFS 摘出、换成本地实际模型或让该 crate 优雅降级。
> **这是 M0 之后、M4 构建之前必须解决的一项**，否则 `crates/input_classifier` 构建会失败。

### 2.4 CI 最小版（若需从零起草）

**原则：CI 就是 presubmit**。不要发明第二套定义。

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  presubmit:
    runs-on: macos-latest      # macOS 必跑（07 §10）
    steps:
      - uses: actions/checkout@v4
      - run: ./script/bootstrap --skip-common-skills   # 见 §5：必须跳过网络 skill 拉取
      - run: ./script/install_cargo_test_deps
      - run: ./script/presubmit
```

> **`--skip-common-skills` 是必须的**（`script/bootstrap:115`）——否则 CI 每次都会从
> `raw.githubusercontent.com/warpdotdev/common-skills` 下载脚本并执行
> （[02 §5.5](02-现状审计.md#s5-5)）。

`.PSScriptAnalyzerSettings.psd1` 若没回来：要么补一个空配置，要么把
`script/lint_powershell` 改成不依赖它。**现状下 presubmit 第 9 步在有 `pwsh` 的

要在 M0 记进 `known-fail.txt`。

<a id="s6-2"></a>
### 6.2 时机铁律

```
V0 ──────────── V1 ──────────── M2 首次真实使用 ──── V2 发布
 │               │                    ▲
 │               │                    │
 └── 反复重建，本地数据随时丢弃 ────────┘
        改名成本 = 0            改名成本 = 数据目录迁移 + 密钥轮换
```

| 阶段 | 改名成本 | 说明 |
|---|---|---|
| V0 / V1 | **0** | 本地数据是一次性的，随时 `rm -rf ~/.warp-oss` 重来 |
| **M2 首次真实使用之前** | **0** ← **唯一的无痛窗口** | 此时必须一次性定稿全部六处 |
| M2 之后 | 高 | 数据目录里有真实历史（SQLite、设置、主题）；keyring 里有真实密钥。改名要写数据目录迁移 + 用户手工重新输入所有密钥 |

> **执行规则**：R1–R6 **必须作为一个 commit 一起改**。分批改会产生"AppId 变了但
> 数据目录没变"的中间态，那个中间态跑一次就会在两个目录里各留一半数据。

<a id="s7-2"></a>

```toml
# 根 Cargo.toml:26 —— [workspace.package]
authors = ["term4u contributors", "Warp Team <dev@warp.dev>"]
```

30 个显式声明 `authors` 的 crate 应当改为继承 workspace：

```toml
# crates/*/Cargo.toml
authors.workspace = true
```

<a id="s7-3"></a>
### 7.3 三条说明

| # | 说明 |
|---|---|
| A1 | **`authors` ≠ 版权。** Cargo 的 `authors` 字段是元数据，没有法律效力；版权由 `LICENSE-*` 文件与实际的著作事实决定。改 `authors` **不会**减损 Denver Technologies 的版权，也**不会**让 term4u 获得任何权利 |
| A2 | **保留 Warp Team 在列表里是诚实的做法。** 这些 crate 的绝大部分代码确实是他们写的。删掉会给人"这是我写的"的错觉 |
| A3 | **不要在 `authors` 里写个人邮箱**，除非愿意它出现在每一份构建元数据里 |

## 八、改名边界线

<a id="s8-1"></a>
### 8.1 改什么

| 类别 | 改 |
|---|---|
| **运行时身份** | R1–R6 六处（[§6.1](#s6-1)） |
| **对外品牌** | B1–B14（[04 §9.5](04-残余依赖与许可证架构.md#s9-5)） |
| **文档** | [§3](#s3) 的重写矩阵 |

<a id="s8-2"></a>
### 8.2 不改什么

| 类别 | 例子 | 理由 |
|---|---|---|
| **crate 名** | `warp_core`、`warp_terminal`、`warp_util`、`warpui`、`warpui_core`、`warpui_extras`、`warp_tui`、`warp_errors`、`warp_features`、`warp_logging`、`warp_files`、`warp_js`、`warp_cli`、`warp_assets`、`warp_completer`、`warp_ripgrep`、`warp_search_core`、`warp_web_event_bus`、`warp_graphql_schema` | 改一个 crate 名 = 改它所有依赖方的 `Cargo.toml` + 所有 `use` 语句。19 个 crate 会波及数千个文件，**每次上游合并都要重打一遍**。收益为零（用户看不到 crate 名） |
| **内部符号** | `WarpServerConfig`、`ChannelState`、`AppId`、`FeatureFlag`、`warp::run()`、所有 `Warp*` 类型名 | 同上 |
| **环境变量前缀** | `WARP_*`、`WARPUI_*` | `crates/integration/tests/common/mod.rs:28-30` 明确按前缀转发环境变量；改前缀会打断集成测试。且用户几乎不接触 |
| **模块路径** | `crate::terminal`、`crate::ai` 等 | 同上 |
| **`specs/` 与 `agents/specs/` 内容** | 285 + 19 个上游文档 | 只读保留 |

<a id="s8-3"></a>
### 8.3 判断规则

> **一个字符串要不要改，只问一个问题：用户会看到它吗？**
>
> - 用户会看到（窗口标题、Dock 图标、bundle id、数据目录路径、日志文件名、
>   URL scheme、包名、README）→ **改**
> - 用户不会看到（crate 名、类型名、模块路径、环境变量、内部常量）→ **不改**
