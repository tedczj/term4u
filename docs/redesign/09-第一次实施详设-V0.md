## 一、V0 完成后是什么状态

| 维度 | V0 完成后 |
|---|---|
| **数据上报** | **物理不存在**：Rudderstack 传输、TelemetryCollector、Sentry/minidump 上传、cloud-agent OTLP 全部删除；7 个遥测宏是 no-op shim；退出时不落"待发事件"文件 |
| **云模块（叶子）** | **物理删除**：自动更新（含 warp_tui 自更新）、崩溃上报、云 tracing、远程实验、共享会话、远端 server、ambient agents、云环境配置、computer_use、语音、changelog、IAP、voice transcriber |
| **云模块（Agent / Drive / 认证 / ServerApi）** | **代码在、编译过、但不初始化**（`initialize_cloud_app` 在 `offline_hard` 下不编译）；UI 按 [03 §8.4](03-阶段1-云模块删除与离线化.md#s8-4) 降级；即使有漏网调用，socket 层守卫兜底拒绝。**物理删除属 V1（M5/M6）**——这是决策 D4（保 Agent UI 外壳）+ D7（V0 尽快可用）的直接推论 |
| **网络** | 主进程零 DNS 查询、零非 loopback 连接（守卫默认拒绝 + 无 URL 可用，双保险） |
| **本地功能** | 终端/PTY、分栏/标签、编辑器、文件树、主题、keybinding、本地 workflow、本地搜索、本地 MCP、本地 LSP（自动下载被守卫拦，PATH 里有就能用）全部可用 |

| **测试** | presubmit 在 `known-fail.txt` 豁免下通过；测试清单 diff 与 `deleted-tests.txt` 精确一致 |
| **产物** | `term4u`（GUI）与 `term4u-tui`（实验性）两个 bin；日常构建 = **F0**，V0 达成判据含 **F1**（见 [§6.4](#s6-4)） |

## 二、范围：做什么 / 不做什么

**做**（M0–M4）：

1. 基线冻结（工具链、全量构建、测试清单、13 个手工场景的改造前对照、旧 DB 样本）。
2. `offline_hard` 跨 crate feature + socket 对端地址守卫 + 离线 resolver + 8 条守卫测试。
3. `ConnectivityMode` 类型改造（云配置在类型层面不存在）+ `term4u`/`term4u-tui` 双入口 + 删 8 个生成器 bin。
4. `initialize_app` 三分 + `ServerApiProvider` 双后端（178 个方法的 `OfflineApi`）+ `LocalAuthStateProvider`。
5. 四批删除（上报与追踪 / 更新与实验 / 共享与远端 / ambient 与 computer_use）+ Windows 资产（W1–W5）。

**不做**（明确留给 V1/V2，见 [08 M5–M7](08-实施顺序与里程碑.md#m5)）：

| 不做 | 原因 |
|---|---|
| 删 `app/src/auth` 云认证、`app/src/drive`、`app/src/cloud_object`、`sync_queue`、agent 系列（`agent/`、`agent_sdk/`…）、云 MCC/MCP、`ai_assistant` | 与 blocklist 决策互相咬合（145 文件 / 525 处交叉引用），必须 M5 同批；V0 由"不初始化 + 空实现 + 守卫"三层保证它们无行为 |
| 删云 crate（`warp_server_client` 等 11 个） | M6；其中两个 crate 里定义着空实现要用的 trait（[03 §8.6](03-阶段1-云模块删除与离线化.md#s8-6)） |
| `LocalPrivacyPolicy` 固化、LSP 下载代码删除、在线字体拒绝、外链菜单删除 | M5；V0 期间这些路径被守卫兜底，且 `telemetry_config: None` 已让隐私页隐藏遥测开关 |
| 六处改名（AppId/目录/scheme/keyring）、品牌资产 | M7；V0 复用 `Channel::Oss` 身份（`.warp-oss` 目录、`warposs` scheme） |
| `Channel::Offline` 枚举变体 | 不引入（[03 §4.4](03-阶段1-云模块删除与离线化.md#s4-4)：11 处穷尽 match 的成本换不来 V0 的任何东西） |

## 五、工序 1：网络硬拒绝（M1）

按 [08 M1](08-实施顺序与里程碑.md#m1) 1.1–1.7。要点回填：

- feature 传递：`http_client` / `websocket` 定义 `offline_hard = []`，`warp_core` 与 `app`
  转发（[03 §6.2](03-阶段1-云模块删除与离线化.md#s6-2)）。
- 守卫 `check_peer`：**默认拒绝**、只放行 loopback；加在 `execute_inner`、
  **单独加在 `eventsource`（`lib.rs:499`，绕过主路径，最易漏）**、`native.rs:49` 直连、
  `proxy.rs:81` 代理实 socket（这样 loopback 代理→远端 URI 的三个测试不受影响）。
- resolver：`offline_hard` 下非 loopback 主机名**直接失败、不发查询**（零 DNS 是验收项）。
- **门禁的产物是 `cargo run -p warp --bin warp-oss --features offline_hard`**——
  term4u bin 还不存在；warp-oss + 守卫 = "生产 URL 在配置里也发不出去"，正是 H4 的演示。
  日志里的连接被拒/重试报错属预期，只看 lsof（V3）与 DNS（V4）两个硬指标。

## 十一、本地日志与故障/性能数据：保证不丢

存量盘点见 [03 §9.5](03-阶段1-云模块删除与离线化.md#s9-5)。结论：**删除的只是
Rudderstack / Sentry / OTLP 三条出网通道；本地诊断链路（`log::*` → `warp.log`、
日志轮转、panic 进日志、日志打包 zip、`dump-debug-info`）一条不动。**

第一次实施把它做成三条**可执行验收**（A11）：

```bash
# L1. 正常运行产生本地日志且在写入
./target/debug/term4u & PID=$!; sleep 10; kill $PID
ls -la ~/.warp-oss*/  | grep -i log            # 日志文件存在且 mtime 新鲜

# L2. panic 进本地日志（不需要 Sentry）—— 用 S12 的 debug 钩子或 kill -SEGV
TERM4U_FORCE_PANIC=1 ./target/debug/term4u; grep -ri 'panic' <日志文件> | tail -1

# L3. 日志打包（UI 菜单 "generate log bundle"）仍产出 zip，全程 lsof 零外连
```
